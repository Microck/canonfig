# Backup verification

All behavioral proof used synthetic fixtures. The real benchmark corpus stayed on the local machine and was never sent to Raft, Git or cloud storage.

## Destination and preset proof

Run in the disposable Raft workspace as its unprivileged `canonfig-proof` user:

```sh
CANONFIG_BACKUP_PROOF=disposable-raft node docs/research/279-backup/proof.mjs destinations /tmp/canonfig-279-destinations.json
```

[`destination-proof.json`](destination-proof.json) records byte-identical encrypted restores for fast, balanced, small and max, including restore drills. Wrong-password recovery left no destination. Local bare Git, rclone local and Forgejo 17.0.1 over SSH round-tripped. A plausible token in an ordinary instruction file blocked plaintext Git publication and left the snapshot set unchanged.

This proves the Git and rclone transports against disposable implementations. It does not claim a live upload to GitHub, GitLab, Google Drive, S3, B2, WebDAV or SFTP. Those providers' authentication and quotas remain operator configuration.

## Source, native credentials and scheduling

```sh
CANONFIG_BACKUP_PROOF=disposable-raft \
HOME=/home/canonfig-proof XDG_RUNTIME_DIR=/run/user/1001 \
DBUS_SESSION_BUS_ADDRESS=unix:path=/run/user/1001/bus \
node docs/research/279-backup/proof.mjs source-follower /tmp/canonfig-279-source-follower.json
```

[`source-follower-proof.json`](source-follower-proof.json) records:

- A Follower enrolled with the disposable Source, applied its signed backup policy, created a verified backup and ran a restore drill.
- A recovery drill and a restore refused at an occupied destination removed their newly allocated native references without removing existing credentials.
- Offline recovery preserved the signing key, TLS key/certificate and shared-secret bytes, plus the Follower registry. All recovered credentials used fresh native Secret Service references. The previously enrolled Follower authenticated and synchronized with the recovered Source.
- Applying the Source's updated policy installed native systemd user timers. The backup and drill timers actually fired, both services exited 0, and the backup created a new snapshot. Disabling the policy removed both schedules.
- Locking the proof keyring made recovery return Human Action Required (exit 3). No destination appeared. A syscall trace found no plaintext recovery-credential or decrypted-tar writes.

The proof owns a private D-Bus session and foreground GNOME Keyring. It stops both before removing their storage. The Follower's native scheduler uses only the disposable user's systemd session. The host credential store and live schedules were not used.

## Limits

Native scheduler and secure-store behavior were exercised on ARM64 Linux. macOS Keychain/launchd and Windows Credential Manager/Task Scheduler were not exercised on native hosts. No human testing has happened; the maintainer will test before merging.

## GUI proof

The production UI ran against the real compiled CLI with a synthetic Source, a disposable HOME and `CANONFIG_LOCAL_CREDENTIAL_ROOT` inside its private temporary directory. This GUI check used the isolated file credential store; native-store recovery is proved separately above.

Through the browser, created a local policy, ran a backup, listed snapshots, verified the snapshot, ran a restore drill and confirmed restoration into a new HOME. Both `canonfig.jsonc` and `AGENTS.md` were byte-identical to the inputs. The snapshot panel and entered restore path survived verification and drill refreshes. Restore required explicit confirmation.

The browser exposed an invalid HTML pattern for policy names and outdated Takeover Snapshot help. After rebuilding, a name containing a period failed browser validation, a hyphenated name saved successfully, and the help described Portable Backups. No new console errors appeared after the corrected build loaded.

Final UI commands: `npm run ui:lint` (0 errors, 73 warnings) and `npm --prefix ui run build -- --outDir /tmp/canonfig-279-final-ui` (passed). The separate output directory avoided modifying the package assets used by the concurrent core suite. [Screenshot](gui-backups.png). The proof tab was closed afterward.

The final production build was also checked with a newly enrolled Follower and its Source. Both exposed offline recovery; only the Source exposed in-place Canonical Folder restore. The Follower's help explained that its Canonical Folder comes from the Source. [Follower screenshot](gui-follower-backups.png). These fixtures used private HOME/XDG paths, file-backed synthetic credentials and an unavailable private D-Bus address, not the live user bus. T3's browser preview completed the check after the standalone browser runners were unavailable. The preview and GUI services were closed afterward.

`gitleaks git --staged --pre-commit --redact --ignore-gitleaks-allow --no-banner .` scanned the staged feature and research changes and found no leaks. The disposable GUI server was stopped and its temporary HOME, credential store and package assets were removed.
