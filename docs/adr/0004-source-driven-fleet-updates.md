# Source-driven Fleet Updates without a follower daemon

The Source Machine selects its own exact stable Canonfig release for a staged Fleet Update. Every enrolled Follower Machine accepts Source-driven Fleet Updates automatically and checks at the start of `sync --apply`, including native scheduled invocations. Enrollment grants this authority; no follower-side enable step or fleet off switch exists. A canary runs first; the Source admits one follower at a time and advances only after the new executable reports a fresh Converged run. A failed health check halts the rollout. This retains one-way authority and native scheduling at the cost of schedule latency; there is no immediate push or resident follower updater.

Update control is authenticated and pinned to the enrolled Source but independent of the configuration transport's major.minor gate, so an older follower can repair release skew. A Source-signed directive binds the follower, rollout sequence, exact release, digest, state format and expiry. Source signing alone cannot authorize code: each follower independently verifies the official npm registry signature, tarball integrity and Sigstore provenance for Canonfig's main-branch release workflow. Arbitrary packages, registries, URLs, commands and downgrades are not directive inputs.

The maintainer accepts that a compromised Source can start a rollout without local approval, but only of an official Canonfig release that passes the npm signature, tarball integrity and release-workflow provenance checks. Removing per-follower consent makes enrollment the single authority boundary rather than requiring a second local configuration step.

Activation reuses the existing self-updater and its gate, command leases, journal and retained prior package. Supported installed commands participate in coordination even when standalone self-updates are disabled. Fleet activation discovers npm beside the running Node executable and does not read standalone opt-in settings as authorization. The standalone self-update off switch remains limited to manual and periodic self-updates. Active or unfinished Synchronization Runs prevent activation. State formats are not migrated. Code rollback after Projection cannot promise configuration rollback, so failure stops admission and retains evidence for the existing explicit recovery procedure rather than automatically reversing packages.

Health identifies both the completed local run and the published Source revision recorded in that run's revision lineage. A follower's content-addressed projection revision is not a Source publication ID; the Source checks the published ID without discarding the local run evidence.
