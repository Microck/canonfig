---
title: Keep version history
description: Save Canonical Folder versions in Git and restore an earlier revision.
---

History keeps a plaintext Git commit for each new Profile Revision you publish.
On an unenrolled machine, `sync --apply` records a commit when it converges and
the authored files have changed. Followers use the Source's history.

## Turn on history

Install Git. On a Source, open **Settings → History**, turn on **Record history**
and save. To turn it on from the CLI, run:

```bash
canonfig history enable
```

For an off-machine copy, create an empty Git repository and install gitleaks.
Set the Git remote in **Settings → History**, click **Check**, then save. From the
CLI, pass the remote when you enable history:

```bash
canonfig history enable --remote git@github.com:maria/agent-config.git
```

Git uses your SSH settings or credential helper. The remote branch defaults to
`main`. Use `--branch <name>` to choose another branch. History starts with your
next new publication or converged apply and contains the eight authored entries
of the Canonical Folder. Machine-local files stay on the machine.

## Check what changed

```bash
canonfig history
canonfig history diff 6 7
```

Use a Profile Revision number or at least seven hex characters from a commit ID.
With one revision, `diff` compares it with the latest commit. Diffs up to 1 MiB
appear in the terminal or inline in Settings.

If a remote is offline, Canonfig keeps the commit and retries on the next
publication or apply. Run `canonfig history push` to retry now. Canonfig uses
fast-forward pushes and reports when the remote branch has diverged.

Gitleaks scans the whole history before a push. Removing a secret in a later
commit leaves it in the earlier commit, so the push stays blocked. Rotate any
exposed credential and keep the affected history local.

## Restore an earlier version

Restore replaces the authored files and removes any authored entries absent from
the selected commit. Settings → History asks for a reviewer before it restores
and publishes. From the CLI on a Source, run:

```bash
canonfig history restore 6 --reviewer Maria
```

Restoring older content publishes it as the next Profile Revision when it differs
from the current revision. On an unenrolled machine, use the commit ID and omit
`--reviewer`. Canonfig runs Projection and records an Apply entry if the tree
changed.

The result includes a Takeover Snapshot when Canonfig replaced or removed folder
entries. Use `canonfig restore <snapshot>` to recover those entries. If the
History restore added an entry absent from the snapshot, remove that entry by
hand when undoing the restore. History restore reads up to 256 MiB of Git blob
data and uses the same apply limits as archive import.

Run `canonfig history disable` to stop capture and pushes. You can still inspect
and restore the saved commits.
