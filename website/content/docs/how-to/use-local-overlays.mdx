---
title: Replace a published item on one machine
description: Use a Local Overlay so one machine's own skill, rule, MCP server, or settings replace the published item with the same name.
---

A local item with the same name as a published one normally stops the sync
with Human Action Required (exit 3), because Canonfig will not choose between
them. A Local Overlay records that this machine's item wins on this machine.

## Before you start

- The Source Machine's `local.allow` must admit the category. See
  [Add items to one machine only](/how-to/add-machine-local-items).
- Overlays live in `~/.canonfig/local/local.jsonc`. They are never published,
  never mirrored, and a new revision does not change them.

## Replace a published item

Add your item under `~/.canonfig/local/`, for example an MCP server in
`local/local.jsonc`, then record the overlay and sync:

```bash
canonfig overlay set mcp/docs
canonfig sync --plan
canonfig sync --apply
```

An item is `rules/<id>`, `skills/<name>`, `agents/<id>`, `commands/<id>`,
`mcp/<name>`, or `settings/<harness>`. For settings, each local key replaces
the published keys it overlaps, and the other published keys stay.

## See and remove overlays

```bash
canonfig overlay list
canonfig overlay remove mcp/docs
```

`list` reports each overlay with `local` (your item exists and is admitted)
and `published` (the Source Machine publishes an item of that name). A plan
warns about an overlay that finds no local item. After `remove`, the next sync
stops with the name collision again until you rename or remove your item.
