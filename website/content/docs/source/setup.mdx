---
title: Set up the Source Machine
description: Initialize source identity and confirm the local Canonfig runtime before publication.
---

Use a machine with Node.js 24 or newer and an installed `canonfig` executable.
The current source transport binds only to a loopback address; do not document
or attempt a public bind.

## Initialize source identity

Run this once in the user account that will own Canonfig:

```bash
canonfig source init
```

Initialization creates source identity and signing material through the
platform credential seam. It does not publish a Machine Profile.

<Callout title="Keep source material private" type="warn">
  Do not copy signing keys, generated credentials, invitation payloads, or the
  Canonfig SQLite database into a repository. Canonfig profile content should
  reference credentials instead of embedding values.
</Callout>

## Check the installation

```bash
canonfig doctor --no-input --timeout-ms 5000
```

`doctor` checks the Node runtime, SQLite state, credential capability, configured
source reachability, native scheduler, package managers, and agent adapter. A
fresh Source Machine may report skipped follower-specific probes.

## Inspect published profiles

```bash
canonfig profile list
```

An initialized source can have no revisions. Publication is a later, explicit
step.

## Run the local source endpoint

```bash
canonfig source serve --host 127.0.0.1 --port 17342
```

The command serves authenticated enrollment and revision transport over HTTPS.
The shipped CLI accepts `127.0.0.1` or `::1` only. TLS identity and the source
signing identity are pinned separately during enrollment.

For structured automation output, place the global `--json` option anywhere in
the invocation:

```bash
canonfig source serve --host 127.0.0.1 --port 17342 --json
```

The process remains active while serving. Stop it through the process manager or
terminal that started it.
