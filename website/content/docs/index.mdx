You keep one folder, `~/.canonfig/`, with your agent setup: instructions,
rules, skills, subagents, commands, MCP servers, hooks, settings, and the tools
they need. Canonfig writes that folder into the global configuration of
listed harnesses that are installed and included on this machine. It
translates the setup into each harness's own files and formats. This is a
**Projection**.

The machine where you edit the folder is the **Source Machine**. It publishes
the folder as a signed **Profile Revision**. Each **Follower Machine** checks
the signature, mirrors the folder into its own `~/.canonfig/`, and projects it
into the harnesses installed there. Follower Machines never send changes back.

By default, before Canonfig first writes to a harness, it copies the content
it will replace into a **Takeover Snapshot** under `~/.canonfig/.backups/`.
`canonfig restore` can put that content back.

Try the [interactive demo](https://canonfig.micr.dev/demo/) to explore the
browser interface with simulated machines. After installing, open the live
workspace for this machine with [`canonfig ui`](/docs/reference/cli#browser-interface).

## Set up with an agent

Paste this prompt into Claude Code, Codex, or any agent that can run shell
commands:

```text
Set up Canonfig on this computer.
1. Install it: npm install --global @microck/canonfig@latest
2. Install its agent skills: npx skills add https://github.com/Microck/canonfig.git --skill '*' --global --yes
3. Follow the skill named setup-canonfig. If new skills only load after a restart, read ~/.agents/skills/setup-canonfig/SKILL.md.
```

The setup skill inspects this computer first, explains what will change, and
waits for your approval before it writes anything.

## What Canonfig does not do

- It does not sync in both directions. A change made in a Follower Machine's
  mirror stays there as Follower Drift and never reaches the Source Machine.
- It does not touch a harness's logins, sessions, history, or trust decisions.
  In files a harness shares with its own state, such as `~/.claude.json`,
  Canonfig changes only the keys it owns.
- It does not publish arbitrary files. Only the folder's authoring entries
  reach Follower Machines.
- It does not run a hosted service. Your Source Machine serves the Profile
  Revisions.
- It does not guarantee that a third-party installer can be rolled back.

To learn which machine owns what and what one run can roll back, read
[How Canonfig works](/docs/explanation/architecture).
