---
title: Synchronization, apply, and verification
description: Plan first, apply the recorded plan, and evaluate independent verification evidence.
---

Each **Synchronization Run** targets one authenticated, immutable Profile
Revision. Canonfig persists a complete plan before its first mutation.

## Plan without changing the follower

```bash
canonfig sync --plan
```

`sync` defaults to plan mode, but the explicit flag is clearer in runbooks. Plan
mode authenticates the follower, fetches and verifies revision metadata,
downloads required content-addressed blobs, loads Applied Resource Records and
the Local Overlay, observes targets, and returns the resulting action graph
without applying it.

Review:

- the targeted Profile Revision and follower;
- transfer, no-op, deterministic, agent, human, and conflict actions;
- dependency order;
- every target and verification method.

## Apply

```bash
canonfig sync --apply
```

Apply mode persists the plan, journals each action, runs deterministic actions
in dependency order, resolves eligible Agent Tasks under the current policy,
and verifies every required resource.

For a scheduler or another noninteractive caller:

```bash
canonfig sync --apply --no-input
```

A successful human-format scheduled apply is intentionally quiet. Failures
remain on standard error with a distinct exit code. With `--json`, success and
failure use the stable `canonfig.cli/v1` envelope.

```bash
canonfig sync --apply --no-input --json
```

## Incremental transfer

Canonfig fetches revision metadata first, verifies the source signature, and
downloads only missing blobs. Cached blobs are addressed by digest. A second
unchanged synchronization reuses them rather than transferring content again.

<Callout title="A downloaded blob is not applied state" type="info">
  Blob transfer can complete while apply or verification fails. Inspect the run
  outcome and action evidence; cache presence is not Convergence.
</Callout>

## Independent verification

Deterministic writes and agent-applied actions use the verification contract
declared by the Profile Resource. Canonfig records command output, status,
digests, or credential observations as appropriate. Agent text is never accepted
as proof by itself.

A run becomes `Converged` only when every required verification passes.
Otherwise the final outcome is `HumanActionRequired`, `FollowerDrift`, `Failed`,
or `Interrupted`.

## Inspect state

```bash
canonfig status
```

Source operators can request status for a specific follower:

```bash
canonfig status --follower follower-one
```

Use structured output for automation:

```bash
canonfig status --json
```
